# 第一张地图与回合制 RPG：开源参考

核验日期：2026-10-05。现有项目继续使用横屏 Canvas 2D。以下参考只用于演出组织和数据规则，本轮未复制这些仓库的源码或素材，也未安装、运行远程代码。

## 1. Phaser：技能演出与粒子绘制

- 仓库：[phaserjs/phaser](https://github.com/phaserjs/phaser)。核验版本为 **v3.90.0**，固定提交 `a9965625f49cf366584f454556b039e06e8adad6`，代码许可证为 [MIT](https://github.com/phaserjs/phaser/blob/a9965625f49cf366584f454556b039e06e8adad6/LICENSE.md)。
- 具体源码：[TweenChain.js](https://github.com/phaserjs/phaser/blob/a9965625f49cf366584f454556b039e06e8adad6/src/tweens/tween/TweenChain.js#L393) 按时间增量推进当前动作，完成后切换下一段；[AnimationState.js](https://github.com/phaserjs/phaser/blob/a9965625f49cf366584f454556b039e06e8adad6/src/animations/AnimationState.js#L193) 管理帧时长和重复；[ParticleEmitterCanvasRenderer.js](https://github.com/phaserjs/phaser/blob/a9965625f49cf366584f454556b039e06e8adad6/src/gameobjects/particles/ParticleEmitterCanvasRenderer.js#L81) 合成透明度、旋转、缩放和 Canvas 绘制状态。
- 建议借鉴：把一次技能表现串成“起手 → 轨迹或冲击 → 命中闪光/飘字 → 收势”，共享时间进度；不同职业通过颜色、轨迹和粒子形状区分。保留现有 Canvas 实现，无需引入 Phaser。

## 2. RPGJS：职业、技能、行囊和装备规则

- 官方仓库：[RSamaium/RPG-JS](https://github.com/RSamaium/RPG-JS)，由 [RPGJS 官网](https://rpgjs.dev/) 的 GitHub 链接确认。核验分支为 **v5**，固定提交 `2560a72fa9ca8b33ef9b61e69003e58872e4f344`，代码许可证为 [MIT](https://github.com/RSamaium/RPG-JS/blob/2560a72fa9ca8b33ef9b61e69003e58872e4f344/LICENSE)。
- 具体源码：[ClassManager.ts](https://github.com/RSamaium/RPG-JS/blob/2560a72fa9ca8b33ef9b61e69003e58872e4f344/packages/server/src/Player/ClassManager.ts#L147) 读取 `skillsToLearn`，检查等级并避免重复学习；[SkillManager.ts](https://github.com/RSamaium/RPG-JS/blob/2560a72fa9ca8b33ef9b61e69003e58872e4f344/packages/server/src/Player/SkillManager.ts#L568) 检查已学技能和技能消耗；[ItemManager.ts](https://github.com/RSamaium/RPG-JS/blob/2560a72fa9ca8b33ef9b61e69003e58872e4f344/packages/server/src/Player/ItemManager.ts#L548) 检查物品持有与使用条件，调用效果后扣除数量，同文件的 `equip()` 检查装备持有和职业条件。
- 建议借鉴：用职业数据表维护每职业4个技能和 3/5/10/15 级进阶解锁，普通攻击另列；行囊把药品定义、持有数量、恢复效果分开；六个装备部位由现有项目的固定槽位规则管理。RPGJS 的实时战斗框架不直接适用当前回合制规则，普通/变异宝宝生成与捕获也保留本项目独立实现。

## 3. Colyseus examples：未来队伍同步

- 仓库：[colyseus/colyseus-examples](https://github.com/colyseus/colyseus-examples)。核验分支为 **master**，固定提交 `ae39826b6348edfdc4f1a67bed634c6468b409f4`，代码许可证为 [MIT](https://github.com/colyseus/colyseus-examples/blob/ae39826b6348edfdc4f1a67bed634c6468b409f4/LICENSE)。
- 具体例子：[02-state-handler.ts](https://github.com/colyseus/colyseus-examples/blob/ae39826b6348edfdc4f1a67bed634c6468b409f4/src/rooms/02-state-handler.ts#L9) 以 `sessionId` 保存成员状态，通过 `onMessage` 接收操作，在房间中更新状态，并处理加入/离开；[04-reconnection.ts](https://github.com/colyseus/colyseus-examples/blob/ae39826b6348edfdc4f1a67bed634c6468b409f4/src/rooms/04-reconnection.ts#L11) 给断线用户提供重连窗口。
- 建议借鉴：将来联网时由房间统一核验“入队、离队、战斗指令”，客户端只提交意图。状态示例的 `maxClients` 为 **4**，不能直接当作本项目五人队伍实现。当前本地五人组队界面不需要增加服务端依赖。

三个仓库本轮均为**思路参考，未复制源码**。代码许可证已核验；若后续实际复制代码，应保留原版权及 MIT 许可说明，素材授权需按具体资源另行核验。

核验方式：网页工具读取官方官网和仓库页；固定提交的源文件与许可证通过 GitHub Contents API 或官方 raw 地址只读获取。未执行其中任何代码。
